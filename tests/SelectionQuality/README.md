# Selection verification probes

After a locked Release build, run `dotnet fsi tests/SelectionQuality/Properties.fsx` from the checkout. FsCheck 3.6.0 is pinned in the script. It checks three properties with 1,000 cases each and replay seed 91557096206384, then runs 2,000 bounded malformed regex inputs with seed 20261024. FsCheck shrinks failing string inputs by deletion and reports the replay and minimized counterexample. A successful run has no failed counterexample to retain. Regex rejection and explicit match timeout are permitted fuzz outcomes; unexpected exceptions fail. Replay seeds reproduce the inputs; permitted timeout observations also depend on scheduling and are not required to repeat exactly.

Select the local SDK using CS_DOTNET_ROOT or DOTNET_ROOT, then run `dotnet run --file tests/SelectionQuality/Mutations.cs -- <checkout>`. The C# file-based app copies the actual public selector implementation into an isolated ignored build directory. The unchanged control must compile and pass. Each of seven deliberate mutants must compile and be detected by its acceptance probe. Compiler failures and surviving mutants fail the command. The command retires any prior advertised result before reading source or building, so a failed attempt cannot leave an earlier success report. Semantic probes use an explicit one-second finite budget; the unit suite checks the public default separately. The JSON report retains the production-source hash, control, mutant outcomes and distinguishing probe messages. This measures selector configuration and matching; it does not measure planner or simulator-runtime mutation strength.

These probes supplement malformed-input unit tests, simulator failure contracts and line/branch coverage. Neither generated samples nor mutation outcomes establish full semantic parity. NativeAOT instructions and HDL coverage require separate measurement.
`PlannerMutations.cs` isolates the production metadata planner and checks one control plus five targeted changes: stage order, constant seeds, filter union, duplicate acceptance and premature body invocation. Each mutation must compile and fail its named discriminator; a crash, compiler failure or unrelated exception is not a killed mutant. Runtime skip/leak behavior and actual simulation remain separate qualifications. Run only after the Release core build, with the pinned SDK root selected. Completion JSON is retired before source reads or builds so failed attempts cannot advertise old success.
After a Release protocol build, run `dotnet run -c Release --file tests/SelectionQuality/NativeThroughputMutation.cs -- <checkout>`. This test-only friend-assembly harness requires the configured native adapter, Icarus and SDK environment. The unchanged R013 control must pass both real runners. A separate coherent RTL variant refuses simultaneous full-stage replacement while consuming the old output; both runners must fail exactly the per-cycle input-acceptance assertion with master seed83 and full-order case seed95. Compiler failures, interrupted/truncated captures and unrelated assertions are invalid evidence. The source HDL and fixture binary hashes must stay unchanged. This is one local RTL-fixture mutant, separate from production C# mutation counts and unmeasured HDL line/branch coverage. The verifier's JSON reflection setting does not change production Runner configuration.

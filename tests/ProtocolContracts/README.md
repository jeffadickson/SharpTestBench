# Local protocol and selection contracts

The RTL is locally authored qualification code, not an imported IP implementation or external protocol certification. The CRC stage uses MSB-first polynomial0x107 (eight-bit representation0x07), initial zero, no reflection and no final XOR. Each accepted last byte resets the accumulator for the next packet. Output length is an unsigned16-bit accepted-byte count; the model preserves the entire packet for CRC computation while exposing length modulo2^16. The current payload scenarios reach513 bytes; they do not qualify every16-bit length or wraparound. The literal `123456789`→`0xf4` check is documented by the primary [pycrc model list](https://pycrc.org/models.html) and [check-value definition](https://pycrc.org/pycrc.html). No pycrc implementation code or generated RTL is used.

The arbiter grants the first requesting port in a rotating priority order. Enable suppresses grants; only acknowledged winners move priority. It does not lock ownership while a request is held. The bank has eight16-bit words, independent low/high byte enables, synchronous read enable with output hold, read-before-write collisions, and dominant reset. C# oracles use whole-message polynomial division, a rotating list, and a word/byte array respectively. Directed and seeded traffic checks accepted transactions, stalls, reset and conservation. Negative controls deposit actual native register faults between clock edges, require output-oracle rejection before consuming a transaction, restore state and check continued operation.

Default entry selects only the implemented `Entry.R###_*` protocol prefix. Separate `ScenarioEntryNN` types bind deliberate selection, list, skip, backend, failure and preflight recipes to the same attested assembly. Some recipes deliberately yield legacy0/native1 because required native manifests reject skips or empty list results. A verified failure boundary is not an all-passed parity claim. Compiler/runner/runtime dependencies are bound by retained input and deployment evidence; simulator test assemblies still need hostfxr/runtime in a separate process, including when the front end is NativeAOT.

Only executed milestones recorded under `docs/development-history/selection200-*` are qualified. Fixture code, declared recipe capacity and RID plans do not establish execution. The four-production-assembly managed coverage excludes this fixture assembly, HDL coverage and NativeAOT instruction coverage.
